# Author a Base

A Base packages one Agent runtime and the contract its entrypoint honors. Write one when you want to run an Agent CLI that RunLab does not already have a Base for.

## Lay out the directory

```text
bases/<name>/
├── Dockerfile
├── entrypoint.sh
├── base.json
└── base.lock        # generated by `runlab base build`
```

## Honor the four-part contract

The image entrypoint must read the complete Task instruction from stdin as UTF-8, run the Agent with `/workspace` as the working directory, write deliverables under `/artifacts`, and exit nonzero when execution fails.

RunLab controls the container command, so the entrypoint takes no arguments from a Task or a caller.

```sh
#!/bin/sh
set -eu

DEEPSEEK_API_KEY="$(cat /run/credentials/deepseek)"
export DEEPSEEK_API_KEY

exec pi --print \
  --provider "${PI_PROVIDER:-deepseek}" \
  --model "${PI_MODEL:-deepseek-v4-flash}" \
  --session-dir /root/.pi/agent/sessions
```

`exec` matters: it hands stdin and the exit status straight to the Agent.

## Leave seams for Overlays

An Overlay must never have to name a runtime flag. Give it fixed paths and environment variables that the Base translates:

```sh
set --
if [ -d /opt/runlab/skills ]; then
  set -- "$@" --skill /opt/runlab/skills
fi

exec pi --print … "$@"
```

Reading configuration from `${PI_MODEL:-…}` does the same for the env form. Both keep the execution contract owned by the Base while letting a capability variable live in its own layer.

## Declare the runtime facts

```json
{
  "name": "pi",
  "output_protocol": "pi-session-jsonl",
  "logs": { "target": "/root/.pi/agent/sessions" },
  "credentials": [
    { "name": "deepseek", "kind": "file", "target": "/run/credentials/deepseek" }
  ],
  "metadata": { "runtime": "pi", "pi_version": "0.83.0" }
}
```

`logs.target` is the absolute directory where the runtime writes its own session files. RunLab mounts `logs/runtime/` there and keeps the files unmodified. The declaration does not switch logging on — the entrypoint must invoke the runtime in a mode that writes them. For Codex, that means not passing `--ephemeral`.

`output_protocol` selects how token usage is derived: `opaque`, `codex-jsonl`, `claude-stream-json`, or `pi-session-jsonl`. Anything other than `opaque` requires `logs.target`, and a Run that declares a usage-aware protocol but yields no parsable usage is a collection failure.

## Pin what you can

Pinning the base image by digest does not replace the lock file, but it removes one source of accidental change:

```dockerfile
FROM node:24-slim@sha256:cd84903a12dbd26b46f1f3b8144a2568c41c5d37ddd0c7a80a34c7a19786b35f
```

Resolve the current digest with `docker buildx imagetools inspect node:24-slim`. Pin the Agent CLI version too — that is usually the fastest-moving dependency in the image.

## Verify before trusting it

```bash
uv run runlab base check bases/<name>
uv run runlab base build bases/<name>
uv run runlab run start --base bases/<name> --task examples/tasks/hello --output runs
```

A successful Run should leave a non-empty `artifacts/`, a non-empty `logs/runtime/`, and a `model_usage` block with no `model_usage_error`. If usage is missing while the protocol is set, the entrypoint is probably not writing native sessions where the declaration says it does.

Commit `base.lock` alongside the declaration. Without it, the next machine builds a different image and every earlier Run stops being a valid control.
